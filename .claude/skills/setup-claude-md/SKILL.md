# CLAUDE.md初期化 + 委任方針セットアップ

新しいリポジトリで最初に1回実行することを想定したスキル。汎用状態から「そのプロジェクト向け」に
一歩進めるのが目的。やることは2段階。

## 1段階目: CLAUDE.mdの調査・作成（/init相当）

`CLAUDE.md`がリポジトリルートに既に存在するか確認する。

- **存在しない場合**: リポジトリを調査し、新規に作成する。調査する内容:
  - 技術スタック（`package.json` / `Cargo.toml` / `go.mod` / `pyproject.toml` 等の依存関係ファイル）
  - ディレクトリ構成（主要なソースコードの置き場所）
  - 既存の `README.md` があれば要約を取り込む
  - ビルド・テスト・lintの実行コマンド（`package.json` の `scripts` 等から実際に存在するものだけ）
  - 既存のコーディング規約が読み取れれば（`.eslintrc` / `.prettierrc` / linter設定等）記載する
  - 存在しないコマンドや未確認の情報を推測で書かない。分からないことは書かないか「未確認」と明記する
- **既に存在する場合**: 内容を尊重し、上書きしない。1段階目はスキップし、2段階目だけ行う。

## 2段階目: agent委任方針のセットアップ

1. `~/.claude/agents/*.md` の存在を確認する。**無ければこのセクション全体をスキップ**し、
   「`~/.claude/agents/` が見つからないため委任方針セクションは追加しなかった」とだけ報告して終了する。
   存在しないagentの一覧を推測で書かない。
2. 存在する場合、各ファイルのfrontmatター（`name`、`description`）を実際に読み取り、一覧表を作る。
   このスキルファイル自体に埋め込まれた古い一覧は使わない——`~/.claude/agents/` の中身は
   `claude-agents` リポジトリ側の更新で変わりうるため、必ずその場で読み直す。
3. CLAUDE.mdに既に「サブエージェント」「委任方針」に類する見出しが無いか確認する。
   既にあれば、**勝手に上書き・重複させず**、どうするかをユーザーに確認する。
4. 無ければ、以下を土台に「サブエージェント委任方針」セクションを追記する
   （見出し文言はリポジトリの他の見出しのスタイルに合わせて調整してよいが、内容の骨子は変えない。
   agent一覧表は手順2で実際に見つかったagentで置き換える）：

   ```markdown
   ## サブエージェント委任方針

   機械的・定型的な作業（ファイル探索、チェック実行、テスト雛形作成、ドキュメントの下読みなど）は
   Task toolでサブエージェントに委任し、可能な限り自身のコンテキストを消費しないこと。
   設計判断・アーキテクチャ選定・デバッグ方針の決定など、判断力が必要な作業は自身で直接処理すること。

   委任するか迷った時点で、原則は委任する。委任しない場合はそれが例外であり、理由を一言添える。

   利用可能なサブエージェント（`~/.claude/agents/`）:

   | 名前 | 用途 |
   |---|---|
   | (agent名) | (descriptionの要約) |
   ```

5. 追記が終わったら、変更したファイルと追記内容の要約をユーザーに報告する。**コミットはしない**
   （差分を確認してからコミットするかどうかは呼び出し元の判断）。

## 注意

- 既存のCLAUDE.mdの内容を破壊的に上書きしない。追記は末尾か適切な位置に追加する形にする。
- 1段階目・2段階目とも、確認していないことを断定して書かない。
- このスキルは **CLAUDE.mdの作成・更新のみ** を行う。project側 `.claude/agents/` を
  そのプロジェクトの実態に合わせて書き換える作業（ドメイン知識の追記など）はこのスキルの範囲外。
  必要であれば別途、実装エージェントに個別に依頼する。
